## 1. 背景

### 1.1 公司与业务
公司是**卡车配件出口外贸型企业**，服务海外经销商、修理厂、车队客户，产品覆盖欧系重卡（Volvo、Scania、MAN、Mercedes-Benz、DAF、Iveco、Renault）的刹车、滤清器、悬挂、离合、冷却、电气、灯具等品类。销售渠道包括邮件/WhatsApp 询盘、Alibaba 国际站、Shopify 独立站和官网。

### 1.2 总经理提出的痛点（原话要点）
> "产品 SKU 数量较大，且有些产品数据不全，我们想打造 AI 产品数据库，能够快速响应客户的需求，从图片到功能再到价格方面。"

拆解为可落地的问题：

| # | 问题 | 现状表现 | 业务影响 |
|---|---|---|---|
| P1 | 询价响应慢 | 客户发来 OE 号 / 竞品号 / 照片，销售需要翻 Excel、问采购、查目录 | 回复慢丢单；依赖老员工经验 |
| P2 | 零件号体系复杂 | 同一个件有多个 OE 号、多个品牌 Cross 号，客户还常写错、带空格横杠 | 找不到件、报错件 |
| P3 | 产品数据不全不一致 | 缺图、缺适配车型、缺包装重量；单位、命名、格式不统一；重复 SKU | 无法上架、无法准确报价 |
| P4 | 供应商资料格式混乱 | 每家供应商 Excel 表头不同，还有 PDF 目录和图片 | 录入靠手工，慢且易错 |
| P5 | 上架内容产出慢 | 英文标题、关键词、卖点、FAQ 需要逐个写 | 上架 SKU 数量受限，平台曝光低 |
| P6 | 经验无法沉淀 | 匹配经验、提示词、客户常见问题散落在个人手里 | 人员流动即流失 |

## 2. 产品目标

### 2.1 MVP 目标
在 **一个可演示的系统** 里跑通「数据进来 → 数据变干净 → 数据被用起来」的闭环：

1. **快速询价**：输入零件号 / 邮件原文 / 图片，秒级给出匹配产品、替代件、供应商成本和建议售价，并生成英文报价。
2. **AI 入库**：供应商 Excel/PDF 上传后自动抽取标准字段并匹配已有 SKU，人工审核后入库。
3. **数据质量可视化**：量化数据完整度，定位重复/缺失/格式问题，并支持一键或 AI 辅助修复。
4. **AI 上架文案**：基于标准数据一键生成 Alibaba / Shopify 英文内容。

### 2.2 成功指标（演示时以演示数据度量，上线后以真实数据度量）

| 指标 | 定义 | MVP 目标 |
|---|---|---|
| 询价响应时间 | 提交询价到出结果（不含人工确认） | 单个号码 < 2s；10 行邮件 < 15s（真实模型） |
| 号码匹配准确率 | Top-1 命中正确 SKU 的比例（基于反馈记录） | 精确号码 ≥ 99%；写错 1–2 位的号码 Top-3 ≥ 85% |
| 供应商资料抽取准确率 | 抽取字段被人工审核直接通过的比例 | ≥ 80% |
| 平均 SKU 完整度 | 质量评分均值（0–100） | 演示中通过修复从 ~70 提升到 ~85 |
| 上架文案产出 | 生成一个 SKU 全套文案耗时 | < 20s |

### 2.3 非目标（本期明确不做）
- 不做登录后的精细权限（仅 Django 超管账号；成本价默认内部可见）
- 不直接对接 Alibaba / Shopify / ERP API（用 CSV 导出代替）
- 不做客户端门户、在线下单、支付
- 不做多语言界面（内部界面中文，面向客户内容英文）
- 不训练/微调模型，只调用通用大模型 API
- 不保证演示数据中零件号的真实性（按格式规则虚构）

## 4. 核心用户故事

- **US-01** 作为销售，我粘贴一封客户英文询价邮件，系统自动拆出每一行零件号和数量，并为每行给出匹配产品，这样我不用逐个查。
- **US-02** 作为销售，客户写错了号码（多了空格、少一位），系统仍能给出最可能的候选并标明置信度。
- **US-03** 作为销售，客户只发了一张照片，系统能识别配件类型和可见号码，推荐候选产品。
- **US-04** 作为销售，我勾选候选产品后，一键生成英文报价邮件和报价单 PDF，价格来自系统中的供应商成本和定价规则。
- **US-05** 作为销售/数据运营，我可以对匹配结果标记「正确/错误」，系统记录下来用于改进。
- **US-06** 作为采购，我上传一个中文表头的供应商 Excel，系统自动识别列含义、抽取为标准字段。
- **US-07** 作为采购，系统把供应商产品和我们已有 SKU 自动匹配，我在审核页批量确认；确认后自动新增 Cross 号和供应商报价。
- **US-08** 作为产品经理，我能在看板上看到 SKU 平均完整度、各类问题数量、各品类完整度排名。
- **US-09** 作为产品经理，我能处理重复 SKU（合并）、一键统一单位格式、接受 AI 给出的缺失字段补全建议。
- **US-10** 作为数据运营，我选择一个 SKU 和平台，一键生成英文标题、关键词、卖点、描述和 FAQ，编辑后保存并导出 CSV。
- **US-11** 作为数据运营，我可以维护提示词模板版本，查看每次 AI 调用的输入输出、耗时和是否成功。
- **US-12** 作为总经理，我打开首页就能看到 SKU 总数、数据完整度、询价量与匹配成功率、AI 使用情况。

## 6. 功能详细说明与验收标准

### 6.1 询价工作台

**流程**
```
输入(文本/号码/图片) → 解析询价行 → 对每行分层匹配(精确→模糊→语义) → 候选列表
→ 销售勾选+填数量 → 计算建议售价 → 生成报价邮件/PDF → 标记反馈 → 保存询价记录
```

**规则**
- 号码归一化：去除空格、`-`、`.`、`/`，转大写；例如 `81.50804-6004` → `81508046004`；带品牌前缀（如 `Knorr K012345`）时自动去掉品牌词。
- 命中方式与置信度：精确号码 100；模糊号码 80–95（按编辑距离相似度映射）；语义 60–80；图片识别在以上基础上再乘 0.9。
- 置信度 ≥ 80 的候选自动选中；语义匹配（< 80）只作为建议，需销售确认。
- 每行最多展示 5 个候选，按置信度降序。
- 建议售价 = 最低有效供应商成本（最近 180 天内报价优先）× (1 + 品类毛利率)，按汇率换算为 USD，保留 2 位小数；**价格永远来自数据库，AI 不参与计算**。
- 无供应商报价时显示「需询价采购」。

**验收标准**
- [ ] 输入精确 OE 号（含空格/横杠变体）能 Top-1 命中，标记「精确匹配 100」
- [ ] 输入错 1 位的号码能在 Top-3 中出现正确产品，标记「模糊匹配」
- [ ] 只输入描述（如 "air spring for Volvo FH"）能返回同品类候选，标记「语义匹配」
- [ ] 粘贴包含 3 行的邮件原文，能拆分为 3 个询价行并分别匹配
- [ ] 上传图片后显示识别出的配件类型/可见号码，并给出候选
- [ ] 候选卡片展示：SKU、主图、OE/Cross 号、适配车型、各供应商成本/MOQ/交期、建议售价
- [ ] 勾选后生成英文报价邮件，内容中的价格与页面一致
- [ ] 可对每行标记正确/错误并保存
- [ ] `AI_MOCK=1` 时以上流程均可完成（解析用正则、图片返回预设结果）

### 6.2 供应商资料 AI 入库

**流程**
```
选择供应商 + 上传文件 → 后台任务：读取 → 列名映射/抽取 → 字段校验与归一化 → 匹配 SKU
→ 审核页人工确认 → 写入：新增 Cross/供应商号码、新增 SupplierOffer、(可选)新建草稿 SKU
```

**标准字段**：supplier_part_no、name、category、oe_numbers[]、cross_numbers[]、brand、specs{}、cost_price、currency、moq、lead_time_days、packaging、weight_kg。

**验收标准**
- [ ] 上传中文表头 Excel 与英文表头 Excel（列顺序不同）都能正确映射到标准字段
- [ ] 上传后页面显示处理进度，不阻塞浏览器
- [ ] 审核页每行展示：原始数据 / 抽取结果 / 匹配 SKU 与置信度
- [ ] 支持单行和批量「通过 / 驳回 / 新建 SKU」
- [ ] 通过后，产品详情页出现新的供应商报价和新增 Cross 号，且不产生重复号码
- [ ] 批次统计：总行数、匹配成功、待新建、驳回数

### 6.3 数据质量看板

**质量规则（首批）**

| 规则代码 | 类别 | 说明 | 严重度 |
|---|---|---|---|
| MISSING_IMAGE | 缺失 | 无产品图片 | 高 |
| MISSING_OE | 缺失 | 无 OE 号 | 高 |
| MISSING_FITMENT | 缺失 | 无适配车型 | 中 |
| MISSING_PACKAGE | 缺失 | 缺重量或包装尺寸 | 中 |
| MISSING_DESC_EN | 缺失 | 无英文描述 | 低 |
| DUP_PART_NUMBER | 重复 | 同一归一化 OE 号挂在多个 SKU | 高 |
| DUP_SIMILAR_NAME | 重复 | 同品类名称+规格高度相似 | 中 |
| FMT_PART_NUMBER | 格式 | 原始号码含非法字符/多余空格 | 低 |
| FMT_UNIT | 格式 | 规格单位不统一（MM/毫米/mm） | 低 |
| FMT_NAME_EN_CJK | 格式 | 英文名中含中文 | 中 |
| STALE_OFFER | 一致性 | 最新报价超过 180 天 | 低 |
| NO_OFFER | 一致性 | 无任何供应商报价 | 中 |

**完整度评分**：见 DESIGN.md §7，按字段加权，0–100。

**验收标准**
- [ ] 看板展示：SKU 总数、平均完整度、问题总数、按规则分布图、按品类平均完整度图、问题清单（可筛选）
- [ ] 「重新扫描」可在数秒内完成全量规则扫描（300 SKU）
- [ ] 单位标准化一键修复后，对应 FMT_UNIT 问题消失，评分更新
- [ ] 合并重复 SKU：号码、适配、报价、图片迁移到保留 SKU，被合并 SKU 标记为归档
- [ ] AI 补全：展示建议值与依据，人工接受后写入，拒绝则不改（MVP 仅补英文名、英文描述；号码/价格/重量/适配不允许 AI 填写）

### 6.4 AI 上架文案

**平台约束（MVP 内置）**
- Alibaba：标题 ≤ 128 字符；关键词 3 个；
- Shopify：标题 ≤ 70 字符（SEO 友好）；标签若干；
- 标题需包含：品类名、关键 OE 号、主要适配品牌/车型。

**验收标准**
- [ ] 产品详情页可选择平台一键生成：标题、关键词、5 条卖点、描述、3–5 条 FAQ
- [ ] 生成内容只引用产品库中已有的号码/规格，不编造（Prompt 约束 + 号码校验：出现库中不存在的号码给出警告）
- [ ] 超出字数限制时提示
- [ ] 可编辑保存，状态：草稿/已确认
- [ ] 可导出已确认文案为 Shopify 产品导入 CSV

### 6.5 AI 基础能力
- [ ] 通过 `.env` 切换模型厂商（base_url、key、model），无需改代码
- [ ] `AI_MOCK=1` 时全部 AI 功能返回确定性的模拟结果
- [ ] 每次调用记录：任务类型、模型、提示词、响应、耗时、token、成功与否
- [ ] 提示词模板可在后台编辑，带版本号；代码按 code 取最新激活版本

### 6.6 首页仪表盘
- [ ] 展示 SKU 总数、平均完整度、待处理质量问题、近 7 天询价数与反馈正确率、待审核入库行、AI 调用次数与平均耗时

## 7. 演示数据要求
- ~300 SKU / 8 品类 / 7 个主机厂品牌 / ~40 车型 / 5 个供应商 / ~600 条历史报价
- 按真实状况注入数据缺口（各问题独立抽样，一个 SKU 可能同时有多个问题）：约 35% 缺图、50% 缺英文描述、35% 缺包装物流、22% 缺适配、30% 缺 Cross 号、8% 缺 OE 号、10% 无报价，另有少量单位混乱、号码格式乱、英文名含中文，以及 6 组重复 SKU；平均完整度约 76
- 2 个供应商 Excel（中文表头 / 英文表头）+ 1 个 PDF 目录
- 3 条示例询价（邮件原文、错号、仅描述）
- 页面显著位置标注 **Demo Data**，所有号码为按格式规则生成的虚构号码

## 8. 演示脚本（约 8 分钟）
1. **首页**：数据资产现状 → "这是现在数据的真实状况"
2. **询价**：粘贴客户邮件（3 行：1 个精确、1 个写错、1 个只有描述）→ 秒出结果 → 一键英文报价
3. **图片询价**：上传刹车片照片 → 识别 → 推荐
4. **入库**：上传中文表头供应商 Excel → AI 映射 → 审核通过 → 产品详情出现新报价和 Cross 号
5. **质量看板**：一键标准化、合并重复、AI 补全 → 完整度分数上升
6. **上架**：为一个 SKU 生成 Alibaba 文案
7. **收尾**：提示词库 + 调用日志 + 反馈记录 = 经验沉淀；后续可对接 RCA-match / Supply-match

## 10. 风险

| 风险 | 应对 |
|---|---|
| 大模型幻觉（编造号码/规格/价格） | 结构化输出 + 校验；号码只从库中取；价格只算不生成；人工审核 |
| 模型接口不稳定/无网络 | Mock 模式兜底；超时与重试；失败可降级为规则匹配 |
| 真实数据质量远差于演示数据 | 规则引擎可扩展；先小批量试点 |
| 成本价等敏感数据外泄 | 发送给模型的内容不含成本价；可切换私有化部署模型 |
| 范围膨胀 | 严格按 P0/P1，P2 进入路线图 |
